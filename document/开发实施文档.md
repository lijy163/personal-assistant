# 开发实施文档

## 1. 文档目标

本文档用于指导“个人辅助系统”的实际开发实施，说明每个阶段要做什么、做到什么程度、产出哪些文件或功能，以及每一步如何交给 AI 辅助完成。

本系统建议采用渐进式开发方式：先搭建基础工程，再完成核心业务闭环，最后逐步接入提醒、股票、调度、Docker、云服务器部署和 AI 辅助能力。

## 2. 总体开发路线

推荐按 8 个阶段推进：

| 阶段 | 目标 | 主要产出 |
| --- | --- | --- |
| 第 0 阶段 | 开发准备 | 技术栈确认、目录规划、环境准备 |
| 第 1 阶段 | 基础工程 | 前端工程、后端工程、数据库、Docker 基础环境 |
| 第 2 阶段 | 登录与系统骨架 | 登录、权限、布局、菜单、统一接口规范 |
| 第 3 阶段 | 核心事项模块 | 生活事项、工作事项、统一事项能力 |
| 第 4 阶段 | 学习成长模块 | 学习计划、学习记录、学习总结、成长看板 |
| 第 5 阶段 | 提醒与调度模块 | 提醒规则、通知通道、定时任务、执行日志 |

## 3. 第 0 阶段：开发准备

### 3.1 确认技术栈

建议默认技术栈：

| 类型 | 技术 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus |
| 后端 | Spring Boot 3 + MyBatis-Plus |
| 数据库 | PostgreSQL |
| 缓存 | Redis，可选 |
| 调度 | Quartz（JDBC 持久化） |
| 数据库变更 | Liquibase |
| 部署 | Dockerfile + Docker Compose |
| 股票分析 | Python 服务，可选 |

### 3.2 需要你确认的事项

开发前最好确认：

1. 前端是否确定使用 Vue 3。
2. 数据库是否确定使用 PostgreSQL。
3. 后端包名，例如 `com.personal.assistant`。
4. 项目根目录名称，例如 `personal-assistant`。
5. 通知 App 第一版接哪个，例如企业微信机器人、钉钉机器人、Bark、Server 酱。
6. 股票第一版关注 A 股、美股、港股还是先只做手动记录。

### 3.3 推荐项目目录

```text
personal-assistant
├── personal-assistant-web
├── personal-assistant-server
├── personal-assistant-python
├── deploy
│   ├── docker-compose.yml
│   ├── nginx
│   └── scripts
└── docs
```

### 3.4 本阶段产出

- 技术栈确认。
- 项目目录确认。
- 本地安装 JDK、Node.js、Docker Desktop、数据库管理工具。
- 明确第一版最小可用范围。

### 3.5 验收标准

- 本地能运行 Java、Node、Docker。
- 项目目录结构明确。
- 已确认第一版不做复杂 AI 和股票策略。

## 4. 第 1 阶段：基础工程搭建

### 4.1 搭建后端工程

要做的事情：

1. 创建 Spring Boot 3 工程。
2. 引入 Web、Validation、Security、MyBatis-Plus、PostgreSQL Driver、Liquibase。
3. 配置多环境文件：`application-local.yml`、`application-prod.yml`。
4. 建立统一返回对象。
5. 建立全局异常处理。
6. 配置 Liquibase changelog，用于管理表结构和初始化数据。
7. 建立基础日志配置。
8. 建立健康检查接口。

推荐后端目录：

```text
personal-assistant-server
└── src/main/java/com/personal/assistant
    ├── common
    ├── module
    ├── integration
    └── AssistantApplication.java
```

本阶段后端接口：

| 接口 | 说明 |
| --- | --- |
| `GET /api/system/health` | 健康检查 |
| `GET /api/system/version` | 系统版本 |

AI 提示词示例：

```text
请基于 Spring Boot 3 创建个人辅助系统后端基础工程，包含统一返回结构、全局异常处理、参数校验、健康检查接口、PostgreSQL 数据源配置和 Liquibase changelog。Controller 不写业务逻辑，公共代码放在 common 包下。
```

### 4.2 搭建前端工程

要做的事情：

1. 创建 Vue 3 + TypeScript + Vite 工程。
2. 引入 Element Plus。
3. 引入 Vue Router。
4. 引入 Pinia。
5. 封装 Axios。
6. 创建基础布局 `AppLayout`。
7. 创建登录页和仪表盘空页面。

推荐前端目录：

```text
personal-assistant-web
└── src
    ├── api
    ├── components
    ├── layouts
    ├── router
    ├── stores
    ├── styles
    ├── utils
    └── views
```

AI 提示词示例：

```text
请创建 Vue 3 + TypeScript + Vite 前端工程结构，使用 Element Plus、Vue Router、Pinia 和 Axios，完成主布局、左侧菜单、顶部栏、登录页和仪表盘占位页。
```

### 4.3 搭建 Docker 基础环境

要做的事情：

1. 创建 `deploy/docker-compose.yml`。
2. 添加 PostgreSQL 容器。
3. 添加 Redis 容器，可选。
4. 配置数据库 Docker volume 或宿主机挂载目录，保证数据不会随容器删除丢失。
5. 预留后端 Dockerfile 和前端 Dockerfile 位置。
6. 数据库表结构和初始化数据不直接写 SQL 初始化目录，统一交给 Liquibase 执行。

建议第一版 Docker 先跑数据库和 Redis，后端与前端先本地启动，方便开发调试；等功能稳定后，再通过 Dockerfile 构建前后端镜像并由 Docker Compose 统一编排。

本阶段产出：

- 后端基础工程可启动。
- 前端基础工程可启动。
- Docker 数据库可启动。
- 前端能请求后端健康检查接口。

验收标准：

- 浏览器打开前端首页无报错。
- 后端健康检查接口返回成功。
- 数据库容器重启后数据仍保留。

## 19. 数据库变更管理规范

### 19.1 Liquibase 使用原则

数据库表结构、索引、初始化数据和后续升级变更统一使用 Liquibase 管理，不使用手工执行 SQL 作为正式交付方式。

原则：

1. 每次表结构变化必须新增 changelog，不直接修改已发布 changelog。
2. 初始化管理员账号、基础字典、默认调度任务通过 Liquibase 初始化。
3. 本地开发、Docker 环境和云服务器环境使用同一套 changelog。
4. 后端启动时自动检查并执行未运行的 changelog。
5. changelog 文件命名要体现顺序和用途。

### 19.2 推荐目录

```text
personal-assistant-server
└── src/main/resources
    ├── application-local.yml

        ├── db.changelog-master.yaml
```

5. 生产环境 `.env` 文件不提交到代码仓库。

## 21. 本地开发环境容器化建议

### 21.1 总体建议

本项目本地开发环境建议采用“一个基础编排文件 + 多个职责单一容器”的方式，不建议把 JDK、Node.js、数据库、Redis、Nginx、数据库管理工具全部塞进一个大容器。

推荐结论：

```text
Docker Desktop 安装在宿主机
Docker Compose 负责启动多个容器
每个容器只做一类事情
数据库和文件类数据必须挂载数据卷
```

### 21.2 为什么不建议放到一个容器

不推荐一个大容器包含所有东西，原因：

1. 升级困难：Node、JDK、数据库任一组件升级都会影响整个容器。
2. 排查困难：日志、端口、进程混在一起，不利于定位问题。
3. 数据风险：数据库和应用放一起，误删容器时更容易影响数据。
4. 不符合 Docker 最佳实践：容器应尽量职责单一。
5. 云服务器部署不方便：生产环境通常也需要拆分服务。

### 21.3 推荐容器拆分

| 容器 | 是否必须 | 作用 | 说明 |
| --- | --- | --- | --- |
| postgres 或 mysql | 必须 | 数据库 | 使用数据卷永久保存数据 |
| redis | 可选 | 缓存和任务锁 | 第一版可不开，后续需要再启用 |
| backend | 必须 | Java 后端运行环境 | Dockerfile 内包含 JRE 或 JDK |
| frontend-build | 构建时使用 | Node.js 前端构建环境 | 用 Dockerfile 多阶段构建，不长期运行 |
| nginx | 必须 | 前端静态资源和反向代理 | 对外暴露 80/443 |
| db-admin | 可选 | 数据库管理工具 | PostgreSQL 用 pgAdmin/Adminer，MySQL 用 Adminer/phpMyAdmin |
| python-stock | 可选 | 股票分析服务 | 后续复杂股票分析再启用 |

### 21.4 JDK 和 Node.js 怎么放进 Docker

#### JDK

后端推荐使用多阶段 Dockerfile：

```text
第一阶段：Maven + JDK 负责编译打包
第二阶段：JRE 或精简 JDK 负责运行 jar
```

这样本机不强依赖安装 JDK，云服务器也只需要 Docker。

#### Node.js

前端推荐使用多阶段 Dockerfile：

```text
第一阶段：Node.js 负责安装依赖和构建 dist
第二阶段：Nginx 负责托管 dist 静态资源
```

这样 Node.js 只存在于构建阶段，生产运行时不需要 Node.js。

### 21.5 Docker Desktop 的位置

`Docker Desktop` 不能放进 Docker 容器里，它是本机运行 Docker 容器的基础软件。

本地电脑必须安装：

1. Docker Desktop。
2. Git。
3. IDE，例如 IntelliJ IDEA、VS Code。

本地电脑可以不安装：

1. JDK，后续可通过后端 Dockerfile 构建运行。
2. Node.js，后续可通过前端 Dockerfile 构建运行。
3. PostgreSQL，数据库通过 Docker 容器运行。
4. Redis，Redis 通过 Docker 容器运行。
5. 数据库客户端，数据库管理工具可通过容器运行。

实际开发时，如果你想获得更好的调试体验，也可以在本机安装 JDK 和 Node.js，但这不是强制要求。

### 21.6 数据库管理工具推荐

如果选择 PostgreSQL：

| 工具 | 部署方式 | 说明 |
| --- | --- | --- |
| pgAdmin | Docker 容器 | 功能完整，适合 PostgreSQL |
| Adminer | Docker 容器 | 轻量，启动快，支持多种数据库 |

如果选择 MySQL：

| 工具 | 部署方式 | 说明 |
| --- | --- | --- |
| Adminer | Docker 容器 | 轻量，推荐 |
| phpMyAdmin | Docker 容器 | MySQL 常用管理工具 |

个人项目推荐优先使用 `Adminer`，因为轻量、简单、同时支持 PostgreSQL 和 MySQL。

### 21.7 本地 Docker Compose 推荐服务

第一版推荐本地 Compose 包含：

```text
postgres 或 mysql
adminer
backend
nginx
```

可选增加：

```text
redis
python-stock
```

前端如果通过 Dockerfile 构建后由 Nginx 托管，则不需要长期运行 Node.js 容器。

### 21.8 推荐开发模式

推荐分两种模式：

#### 模式 A：全 Docker 模式

适合验证部署一致性。

```text
Docker Compose 启动数据库、Adminer、后端、Nginx
前端通过 Dockerfile 构建后放进 Nginx
后端通过 Dockerfile 构建 jar 并运行
```

优点：环境最统一，本机依赖少。

缺点：调试 Java 和前端热更新不如本机方便。

#### 模式 B：混合开发模式

适合日常编码调试。

```text
数据库、Adminer、Redis 用 Docker
后端用 IDE 本地启动
前端用本地 Node.js 启动
```

优点：调试最方便。

缺点：本机需要安装 JDK 和 Node.js。

你的要求是尽量都放 Docker，因此默认采用模式 A；如果后续调试不方便，再临时使用模式 B。

### 21.9 最终推荐

本项目最终推荐：

```text
不要做一个全家桶大容器
使用 Docker Compose 拆分多个容器
后端用 Dockerfile 多阶段构建
前端用 Dockerfile 多阶段构建
数据库和文件数据用 volume 持久化
数据库管理工具用 Adminer 容器
Docker Desktop 只安装在宿主机
```
