# 本地部署文档

## 1. 准备事项

本地必须先启动 Docker Desktop。

项目目录：

```text
个人系统/personal-assistant
```

数据库配置文件：

```text
个人系统/personal-assistant/deploy/.env
```

当前数据库配置：

```env
POSTGRES_DB=personal_assistant
POSTGRES_USER=assistant
POSTGRES_PASSWORD=assistant_password
SPRING_PROFILES_ACTIVE=prod
```

## 2. 启动顺序

### 2.1 启动数据库和 Adminer

```powershell
cd 个人系统\personal-assistant\deploy
docker compose --env-file .env up -d postgres adminer
```

查看容器是否启动：

```powershell
docker ps
```

应看到：

```text
personal-assistant-postgres
personal-assistant-adminer
```

### 2.2 启动后端

```powershell
cd 个人系统\personal-assistant\personal-assistant-server
mvn spring-boot:run
```

后端启动时会通过 Liquibase 自动初始化数据库表。

### 2.3 启动前端

```powershell
cd 个人系统\personal-assistant\personal-assistant-web
npm run dev
```

如果第一次启动前端，先执行：

```powershell
npm install
```

## 4. 常用命令

停止数据库和 Adminer：

```powershell
cd 个人系统\personal-assistant\deploy
docker compose --env-file .env stop postgres adminer
```

查看 PostgreSQL 日志：

```powershell
cd 个人系统\personal-assistant\deploy
docker compose --env-file .env logs -f postgres
```

删除容器但保留数据：

```powershell
cd 个人系统\personal-assistant\deploy
docker compose --env-file .env down
```

删除容器和数据库数据卷，仅开发初期可用：

```powershell
cd 个人系统\personal-assistant\deploy
docker compose --env-file .env down -v
```

## 5. 常见问题

### 5.1 后端报数据库账号密码错误

确认这两个文件中的账号密码一致：

```text
个人系统/personal-assistant/deploy/.env
个人系统/personal-assistant/personal-assistant-server/src/main/resources/application-local.yml
```

都应使用：

```text
assistant / assistant_password
```

如果之前用错误密码初始化过数据库，开发阶段可重建数据卷：

```powershell
cd 个人系统\personal-assistant\deploy
docker compose --env-file .env down -v
docker compose --env-file .env up -d postgres adminer
```

### 5.2 前端健康检查失败

先确认后端是否启动：

```text
http://localhost:8080/api/system/health
```

后端没启动时，前端仪表盘健康检查会失败。

## 6. 一次性启动命令汇总

依次执行：

```powershell
cd 个人系统\personal-assistant\deploy
docker compose --env-file .env up -d postgres adminer

cd ..\personal-assistant-server
mvn spring-boot:run

cd ..\personal-assistant-web
npm run dev
```

## 8. 运维状态与备份恢复

登录后访问“部署运维”页面，可以查看数据库、Quartz、磁盘空间和备份记录。磁盘使用率默认达到 85% 时显示告警，可通过 `STORAGE_WARNING_PERCENT` 调整。

### 8.1 手动备份

容器完整启动后，可在页面点击“立即完整备份”，或执行：

```bash
docker compose --env-file .env exec backend /app/scripts/backup.sh
```

备份包保存在 `personal-assistant-backup` 数据卷，对应容器目录 `/app/backup`，包含 PostgreSQL 自定义格式 dump、文件目录归档和 manifest。默认保留 14 天，可通过 `BACKUP_RETENTION_DAYS` 修改。

### 8.2 定时备份

在“调度管理”中新增任务：

- 任务类型：`DATA_BACKUP`
- Cron 示例：`0 0 3 * * ?`（每天凌晨 3 点）
- 启用：是

任务执行结果记录在调度执行日志和备份记录中。

### 8.3 恢复

恢复会覆盖数据库中的现有对象。先停止前端写入并再次确认备份文件，然后执行：

```bash
docker compose --env-file .env exec \
  -e RESTORE_CONFIRM=YES \
  backend /app/scripts/restore.sh \
  /app/backup/personal-assistant-YYYYMMDD-HHMMSS.tar.gz
```

恢复完成后重启后端并检查 `/api/system/health`、登录、事项数量和最近记录。正式上线前至少完成一次恢复演练。

## 9. 云服务器上线检查

1. 将项目放到 `/opt/personal-assistant`，从 `.env.example` 创建 `.env`。
2. 修改数据库密码和至少 32 字节的随机 `JWT_SECRET`。
3. 数据库端口保持绑定 `127.0.0.1`；如 5432 被占用，设置 `POSTGRES_PORT`。
4. 只对公网开放 80/443，Adminer 和后端 8080 建议仅限管理网络。
5. 在 Nginx 或云负载均衡配置 HTTPS、证书续期和 HTTP 到 HTTPS 跳转。
6. 启动后检查容器健康、磁盘阈值、备份任务和恢复流程。
7. 配置云磁盘快照或异地复制，避免备份与业务数据只存在同一块磁盘。
